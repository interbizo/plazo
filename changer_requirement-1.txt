==========
Saya menemukan kode yang paling relevan untuk keempat temuan. Ini lokasi yang kemungkinan terkait, bukan konfirmasi akar masalah penuh—untuk Boost khususnya, penyebab runtime perlu dipastikan dari data API atau pesan error di browser.

Test	File dan lokasi	Petunjuk dari kode
UI-001 — Notifikasi terpotong	frontend/src/components/shared/notification-dropdown.tsx, baris 97–98, 127–169	Panel memakai overflow-hidden, daftar dibatasi tingginya, dan pesan memakai line-clamp-2. Jadi teks panjang memang dipotong menjadi maksimal dua baris; ini kandidat kuat untuk gejala yang dilaporkan.
UI-002 — Warna tema tidak konsisten	Halaman pengaturan CMS: frontend/src/app/admin/cms/page.tsx, baris 374–402; penerapan warna: frontend/src/components/layout/client-layout.tsx, baris 100–131	Pengaturan Superadmin menggunakan primary_color dan accent_color—bukan secondary_color. Layout menerapkan keduanya sebagai CSS variables. Elemen yang memakai warna Tailwind statis atau tidak memakai variable tersebut tidak otomatis ikut berubah, yang bisa menjelaskan perubahan hanya pada sebagian UI.
UI-003 — Audit log overflow	frontend/src/app/admin/audit-logs/page.tsx, baris 78–104	Deskripsi dan email ditampilkan dalam layout flex. Kolom teks tidak tampak diberi batas lebar atau aturan pemenggalan seperti min-w-0/break-words, sementara tanggal memakai shrink-0. Teks panjang—terutama tanpa spasi—dapat mendorong konten melewati container.
FT-001 — Klik seller di Boost memunculkan error	frontend/src/app/admin/boosts/page.tsx, baris 150–163 dan 294–382	Klik kartu mengatur selectedSeller, lalu tampilan detail langsung membaca seller.products.length, seller.services.length, dan seller.jobs.length. Bila respons API tidak menyertakan salah satu array tersebut, render detail dapat melempar error. Error boundary yang menampilkan pesan “Oops! Terjadi Kesalahan” ada di frontend/src/components/ErrorBoundary.tsx, baris 55–91.
Catatan untuk warna: kalau yang dimaksud adalah warna storefront seller, bukan warna platform Superadmin, pengaturannya berada di frontend/src/app/seller/dashboard/store/page.tsx, baris 763–850. Itu alur terpisah dari pengaturan warna CMS Superadmin.

Untuk memastikan FT-001, langkah berikutnya adalah memeriksa respons getPremiumSellersForBoost dan error di console saat kartu diklik; dari kode frontend saja belum bisa dipastikan apakah penyebabnya data seller yang tidak lengkap atau error lain di render detail.
